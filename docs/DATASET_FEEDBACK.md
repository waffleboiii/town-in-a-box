# Feedback on NVIDIA Nemotron-Personas-France

This feedback comes from the Town-in-a-Box team (Nebius x NVIDIA Global AI Hackathon, October 2026).

**How we used the dataset.** We built a simulated population of about 2,000 residents of Paris and its inner suburbs (départements 75, 92, 93 and 94). A city planner can test a proposal on this population before a public consultation. We took every row for those four départements (**125,211 of the 1,000,000 rows**), re-weighted them to the INSEE 2022 census, and gave each resident a reaction generated by a Nemotron model on Nebius Token Factory.

The dataset made the project possible. The texts are rich and varied, the structured fields are clean (0 nulls in the 13 columns we use), and the CC BY 4.0 licence is easy to work with. DuckDB can filter the 12 Hugging Face shards by département in about 4 minutes, without downloading them.

The findings below are things we had to work around. Each one includes a query you can rerun. All numbers were measured on the October 2026 version of the dataset.

---

## Setup for the queries

```sql
-- DuckDB 1.x / 2.x
INSTALL httpfs; LOAD httpfs;
CREATE VIEW fr AS SELECT * FROM read_parquet([
  'https://huggingface.co/datasets/nvidia/Nemotron-Personas-France/resolve/main/data/train-00000-of-00012.parquet',
  'https://huggingface.co/datasets/nvidia/Nemotron-Personas-France/resolve/main/data/train-00001-of-00012.parquet',
  -- ... same pattern up to ...
  'https://huggingface.co/datasets/nvidia/Nemotron-Personas-France/resolve/main/data/train-00011-of-00012.parquet']);
CREATE VIEW p AS SELECT * FROM fr
  WHERE departement IN ('Paris','Hauts-de-Seine','Seine-Saint-Denis','Val-de-Marne');   -- 125,211 rows
```

INSEE reference figures come from the 2022 census, "base infracommunale" files summed to commune or arrondissement level:

- [Population](https://www.insee.fr/fr/statistiques/8647014)
- [Diplômes - Formation](https://www.insee.fr/fr/statistiques/8647010)
- [Logement](https://www.insee.fr/fr/statistiques/8647012)

Populations come from geo.api.gouv.fr. Our pipeline (`pipeline/build_population.py`) reproduces every number below.

## 1. Paris, Lyon and Marseille are sampled twice

Each of the three cities appears once as the city with no arrondissement, and once more as its arrondissements. The two groups have almost exactly the same size:

| City | rows with commune = city only | rows with an arrondissement |
|---|---:|---:|
| Paris | 30,693 | 30,763 |
| Marseille | 12,196 | 11,971 |
| Lyon | 7,333 | 7,297 |

As a result, Paris has **29.2 rows per 1,000 inhabitants**, compared with 13.65 in Hauts-de-Seine, 12.82 in Seine-Saint-Denis and 13.54 in Val-de-Marne. The arrondissement rows alone give 14.1–16.0 per 1,000 inhabitants, which matches the rest of the region. So the city-only rows look like a second, duplicate draw, as if commune 75056 and the 20 arrondissements 751xx were both in the sampling frame.

```sql
SELECT CASE WHEN commune IN ('Paris','Lyon','Marseille') THEN commune
            ELSE split_part(commune, ' ', 1) || ' (arrondissements)' END AS grp, count(*)
FROM fr WHERE commune LIKE 'Paris%' OR commune LIKE 'Lyon%' OR commune LIKE 'Marseille%'
GROUP BY 1 ORDER BY 1;
```

**Impact.** Anyone who takes per-commune counts at face value over-represents Paris, Lyon and Marseille by about 2×.

**Suggestion.** Keep either the city or its arrondissements in the sampling frame, not both. We recommend the arrondissements.

## 2. Half of the Paris rows have no arrondissement

30,693 of the 61,456 Paris rows (**49.9 %**) have `commune = 'Paris'`. The share is the same for every occupation (49.3–52.5 %), so these rows are a random half, not a particular subgroup.

```sql
SELECT occupation, round(100.0*avg((commune='Paris')::int),1) AS pct_without_arr, count(*)
FROM p WHERE departement='Paris' GROUP BY 1 ORDER BY 2;
```

**Impact.** Arrondissements differ a lot: INSEE gives 25 % cadres in the 19e and 45 % in the 9e. For any neighbourhood-level analysis, an arrondissement has to be imputed for these rows. We impute it jointly with occupation, age and education, using P(arr | occ, age, edu) ∝ P(arr)·P(occ|arr)·P(age|arr)·P(edu|arr) with INSEE shares. Assigning it uniformly at random would be wrong.

## 3. The generator invents an arrondissement when it isn't given one

Among the rows that only say "Paris", **47.3 % (14,523 rows)** still name an arrondissement in their text, for example "ouvrier du 18e" or "la mairie du 12ᵉ arrondissement". **47 % of those mentions are the 12e (7,426 rows)**. Next come the 20e (2,028) and the 11e (1,850). The 12e has about 6.5 % of the Paris population.

For comparison, among rows that do have an arrondissement field, 73.6 % mention one in their text, and **96.8 %** of those mentions agree with the field. So the texts follow the structured field when it exists, and the model makes up a location when it doesn't. The made-up locations cluster on a few arrondissements.

```python
# Python 3 + DuckDB, run after the setup above (same regex as ARR_PATTERN in pipeline/build_population.py)
import re, collections, duckdb
ARR = re.compile(r"(?:(?:\bdu|\bdans le|\bau|\ble|\bParis|\ben plein)\s+(1er|[1-9]|1[0-9]|20)(?:e|ème|eme|ᵉ|er)\b"
                 r"(?!\s+(?:enfant|étage|fois|année|degré|siècle|rang|place|âge))"
                 r"|\b(1er|[1-9]|1[0-9]|20)(?:e|ème|eme|ᵉ|er)\s+arrondissement)", re.I)
def mentions(t):
    return {int((m.group(1) or m.group(2)).lower().replace("er", "")) for m in ARR.finditer(t)}
rows = con.sql("SELECT persona||' '||professional_persona||' '||cultural_background FROM p "
               "WHERE departement='Paris' AND commune='Paris'").fetchall()   # con = your DuckDB connection
found = [mentions(t) for (t,) in rows]
print(sum(1 for f in found if f) / len(rows))                   # share of rows naming an arrondissement: 0.473
print(collections.Counter(a for f in found for a in f).most_common(3))   # 12e first: 7,426
```

**Impact.** In a map-based app, a resident's own text can contradict where they are shown to live. We do not use these mentions as evidence of location. We only avoid drawing residents whose text names a different arrondissement than the one we assigned, which leaves 27 such residents out of 1,400.

**Suggestion.** Put the arrondissement, or the district, into the generation prompt, or tell the generator not to invent sub-commune locations.

## 4. Occupation does not vary by place

The occupation mix (8 INSEE PCS groups) is essentially the national mix in every département and every arrondissement:

| | Dataset: cadres | INSEE 2022 (18+): cadres | Dataset: ouvriers | INSEE: ouvriers |
|---|---:|---:|---:|---:|
| Paris | **9.73 %** | **32.9 %** | 13.10 % | 4.1 % |
| Hauts-de-Seine | 10.13 % | 30.3 % | 13.59 % | 5.2 % |
| Seine-Saint-Denis | 9.95 % | 11.7 % | 14.33 % | 13.4 % |
| Val-de-Marne | 10.23 % | 18.9 % | 13.44 % | 8.6 % |

- **Across Paris arrondissements**, the share of cadres in the dataset ranges from 6.1 % to 11.4 %. INSEE gives 25.2 % (19e) to 44.5 % (9e). The dataset ranking has no relation to the real one.
- **Farmers:** the dataset has 417 "Agriculteurs exploitants" living in Paris (0.68 % of Paris rows), against 0.025 % in the census.

```sql
SELECT departement, round(100*avg((occupation LIKE 'Cadres%')::int),2) cadres,
       round(100*avg((occupation='Ouvriers')::int),2) ouvriers,
       sum((occupation='Agriculteurs exploitants')::int) farmers
FROM p GROUP BY 1;
SELECT commune, round(100*avg((occupation LIKE 'Cadres%')::int),1) cadres
FROM p WHERE departement='Paris' AND commune<>'Paris' GROUP BY 1 ORDER BY 2;
```

**Impact.** Without correction, "Paris" in the dataset is mostly employees, manual workers and retirees, which is the opposite of the real city. For a policy simulation, this changes the results: a votation on SUV parking fees or e-scooters splits along occupation and income lines. We rake every district to INSEE sex × occupation, sex × age and education marginals. Paris cadres then move from 9.7 % to **33.0 %**, against an INSEE figure of 32.9 %.

**Suggestion.** Condition occupation on commune or arrondissement using the INSEE census PCS tables, which are open and published per commune and per arrondissement. Education already partly does this (see finding 5).

## 5. Education varies by département, but too little, and not by arrondissement

The share with Bac+5 or more is 26.0 % in Paris and 11.5 % in Seine-Saint-Denis, so education does depend on the département. INSEE gives 42.3 % and 12.4 % for people aged 15+ who are no longer studying. Across arrondissements, the dataset is flat at 24.2–27.9 %, while INSEE ranges from 28.4 % to 55.2 %.

Inside a row, education and occupation are strongly linked: 80 % of cadres have Bac+5. Because occupation is not geographic but education partly is, the joint distribution comes out odd. For example, Paris has 3,464 retirees and 2,013 people "without professional activity" with Bac+5, against 4,769 cadres.

```sql
SELECT departement, round(100*avg((education_level='Bac+5 ou plus')::int),1) FROM p GROUP BY 1;
PIVOT (SELECT occupation, education_level FROM p WHERE departement='Paris') ON education_level USING count(*) GROUP BY occupation;
```

## 6. Fields a policy simulation needs but the dataset lacks

The dataset has no fields for income or standard of living, tenure (owner, private renter or social housing), car ownership, workplace or commute, nationality (which decides who can vote locally), household size or number and ages of children, disability, or a sub-commune location (IRIS).

All of these drive how people react to urban policy. We had to impute every one of them from INSEE statistics and label them "imputed" everywhere in the app:

- tenure, matched per district to INSEE census shares
- car ownership, matched per district to the INSEE share of households with a car
- foreign nationality, matched per district to the INSEE share of foreign nationals
- workplace and commute mode, calibrated per district to INSEE commute-mode shares

The texts sometimes mention a car or an HLM flat, but not reliably enough to extract these fields. Even a few of them as structured fields would remove a large source of error.

"Autres sans activité professionnelle" also mixes students (8.0 % of rows are aged 18–25) with homemakers and others (7.6 %). A `student` flag would help.

## 7. Names can't be read reliably from the text

The persona text usually starts with "Firstname Lastname, …", and there is no separate name field. Exceptions we hit:

- **23 rows** start with a civil-status artifact instead of a first name, for example "Epse Cavuoto, tranquille et légèrement rêveuse…" or "Epse Le trouve sa stabilité…". Here the name is cut down to "Le".
- About **1.6 % of rows** start with adjectives, as in "Méthodique et réservé, Laurent Demay trouve…" or "Curieux et loquace, Ibrahima Sory Pemba…". Some start with "Un retraité… / Une octogénaire…" and contain no name at all. 2,038 rows match a short list of such openings.

We take the first multi-word capitalised name that another text field of the same row confirms. That leaves 0.03 % of rows needing a fallback name.

```sql
SELECT count(*) FROM p WHERE regexp_matches(persona, '^(Epse|Vve|Née|Ep\.)\s');                 -- 23
SELECT count(*) FROM p WHERE regexp_matches(persona, '^(Méthodique|Curieux|Curieuse|Rigoureux|Rigoureuse|Un |Une |Pragmatique)');  -- 2,038
```

**Suggestion.** Add `first_name` and `last_name` columns, which the generator clearly had, and clean "Epse", "Vve" and "Née" from the source name lists.

## 8. Smaller observations

- **Age ranges look sensible.** Retirees are 50–104 and workers 18–74. There are no minors, as documented.
- **Sex ratio** among the 4 départements: 53.0 % women (INSEE 2022 adults 18+: 52.7 %).
- **Places outside the region:** 22 % of Paris rows mention a French city or region outside Île-de-France, such as "marchés de Strasbourg" or "Bretagne". Many are probably origins or holidays, so these are not necessarily errors. We did not filter on them.
- **Only `country = 'France'`** appears in these départements, although about 15 % of Paris residents are foreign nationals (INSEE). A nationality or citizenship field would be valuable (see finding 6).

---

## What would make the dataset better for civic and policy simulation

1. Fix the double sampling of Paris, Lyon and Marseille, and always give an arrondissement there.
2. Condition occupation, and more strongly education, on commune or arrondissement with INSEE census marginals. Publish the marginal check, dataset against census, per département.
3. Pass the location fields into the text-generation prompt, so texts don't invent arrondissements.
4. Add structured `first_name` / `last_name`, plus some of: tenure, car, nationality, household size, student flag, coarse income band.
5. Document the generation hierarchy: which attributes are conditioned on which geography level.

We are grateful for the dataset. Even with these corrections, it gave our simulated residents a realism we could not have produced ourselves within a hackathon.
